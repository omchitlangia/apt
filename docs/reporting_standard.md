# APT reporting standard

This file is the standing contract every future research unit cites
instead of re-stating reporting expectations. Cite it from your unit
report's top matter; do not duplicate its text.

The module that implements the standard is [`src/apt/reporting/`](../src/apt/reporting/).

------------------------------------------------------------------------

## 1. Required sections (in this order)

The report skeleton in
[`src/apt/reporting/report.py`](../src/apt/reporting/report.py) emits
this list verbatim. Every unit report MUST contain every section. If a
section is genuinely N/A, write `[TODO] N/A — reason: …` rather than
omitting it.

1. **Objective**
2. **Pre-registered expectations**
3. **Config grid**
4. **Headline tables (gross AND net side by side)**
5. **Figures**
6. **Exclusion funnel**
7. **Diagnostics**
8. **Caveats / [TODO]**
9. **Verdict**
10. **Test results**

------------------------------------------------------------------------

## 2. Required figures

Eleven figure types, generated by
[`src/apt/reporting/figures.py`](../src/apt/reporting/figures.py).
**(a), (b), (d), (h) are ALWAYS required.** The rest are required when
applicable; the unit declares "N/A — reason" otherwise.

| letter | function (`fig_*`)              | what it shows                                                                       | always required |
|:------:|---------------------------------|-------------------------------------------------------------------------------------|:---------------:|
| a      | `fig_a_per_pair_fold_equity`    | one panel per (fold, pair), gross + net cumulative log P&L on same axes             | **yes**         |
| b      | `fig_b_portfolio_nav`           | portfolio NAV per cell, gross vs net                                                | **yes**         |
| c      | `fig_c_spread_z_markers`        | spread + Z trajectory of best/worst pair-fold per cell, with entry/exit/stop marks  | when there is a "best" cell |
| d      | `fig_d_cost_ladder`             | net Sharpe and net total return vs cost level per (freq, regime), engines overlaid  | **yes**         |
| e      | `fig_e_a_star_vs_cost`          | a* vs cost per frequency, in Z units AND bps                                        | when an engine produces a* |
| f      | `fig_f_half_life_distribution`  | HL distribution per frequency with band boundaries drawn                            | when HL is fit  |
| g      | `fig_g_drift_chart`             | test-slice Z-OU mean per pair-fold with ±0.5 σ_eq flag lines                        | when an engine carries a frozen mean |
| h      | `fig_h_exit_reason_stacked`     | exit-reason stacked bars per cell                                                   | **yes**         |
| i      | `fig_i_trade_counts`            | trade count by engine × frequency at a fixed cell                                   | when ≥ 2 engines / frequencies |
| j      | `fig_j_beta_histogram`          | (1+β)/2 histogram, all pairs vs traded survivors                                    | when cost convention depends on β |
| k      | `fig_k_exclusion_funnel`        | pair-folds attempted → traded                                                       | **yes** (any selection step)    |

### Figure conventions (enforced by `figures.py`)

* **Output**: `reports/<unit>/figures/<name>.png` + companion CSV
  `<name>.csv` carrying the exact numbers behind the figure. PNG + CSV
  paths returned from each function.
* **Titles**: every figure title includes full cell identity
  (`engine / freq / regime / cost / stop_mode`) when applicable. The
  helper `_cell_title(...)` is used to format this string consistently.
* **Style**: `apt.plots.style.apply_style()` is called inside every
  figure function (idempotent). APT palette only.
* **Library**: matplotlib only. No new plotting dependency may be
  added.

## 3. Number-in-prose rule

**No number may appear in the report prose that is not also in a table
or figure CSV.** If the verdict says "21.2% net annual on n = 2 pair-
folds", that number must appear in the headline table AND in the
figure-(b) companion CSV. Spot-check: if a reader greps the prose for
a number they cannot find in a `.csv`, the report is non-compliant.

------------------------------------------------------------------------

## 4. Gross + net rule

Every metric reported as "net" must appear next to the matching
"gross" in the same row. Never put net on its own line. The headline
table for a unit reports, per cell, AT MINIMUM:

```
n_pair-folds  n_unique_pair_keys  n_trades
gross_total%  net_total%
gross_ann%    net_ann%
gross_Sharpe  net_Sharpe
max_DD%
```

Cost-ladder figures (d) show both `net_sharpe` and `net_total_pct` per
cost level, but each panel carries the matching gross series wherever
the underlying CSV has it.

------------------------------------------------------------------------

## 5. Verdict ordering

Conclusions are written in **order of importance**, not in order of
discovery. When the most-eye-catching finding is exploratory or
narrow-sample (e.g. n = 2 pair-folds), it goes LAST under a clearly-
labelled "exploratory" header. The primary finding is the one that
generalises — usually a structural negative (e.g. "no intraday-
timescale MR exists in this universe") or a methodological constraint
(e.g. "frozen μ_OU is untenable at the observed σ_eq-units drift").

------------------------------------------------------------------------

## 6. `[TODO]` policy

Use `[TODO]` instead of inventing or guessing a number. A `[TODO]` is
information that the writer has chosen NOT to compute (yet). Categories:

- `[TODO scope]` — out of unit's scope; will be covered later.
- `[TODO data]` — the data exists but was not pulled in this round.
- `[TODO compute]` — needs a run we have not done.

Forbidden: `[TODO]` as a placeholder for prose that should just be
written. `[TODO]` is for missing **data or computations**, not missing
words.

------------------------------------------------------------------------

## 7. Exit-reason vocabulary (FIXED)

Five and only five strings. Any backtest engine, signal engine, or
re-stamp helper that emits trades must use these labels and only these:

| label           | meaning                                                                  |
|-----------------|--------------------------------------------------------------------------|
| `mean_revert`   | exit triggered by signal returning to / crossing the exit threshold       |
| `z_stop`        | hard z-stop / OU K-σ stop fired                                           |
| `time_stop`     | max-holding bars elapsed without mean-revert or stop                      |
| `eod_squareoff` | Regime A end-of-session forced close (intraday)                           |
| `fold_close`    | end-of-fold force-close (Regime B) / walk-forward fold boundary           |

`fig_h_exit_reason_stacked` enforces this list; unknown values are
folded into an `__OTHER__` row in the companion CSV.

------------------------------------------------------------------------

## 8. MLflow attachment

If MLflow is wired up (it is **not** at the time of writing —
2026-06-11), every figure must be logged as an artefact to the
unit's MLflow run alongside the metric scalars. When MLflow is not
wired, the figures appendix in the report serves as the artefact
catalogue.

When this changes, update this section first, then teach
`src/apt/reporting/figures.py` to optionally call
`mlflow.log_artifact(png_path)` if a tracker is active.

------------------------------------------------------------------------

## 9. Compliance checklist (paste into PRs)

```
[ ] Section list matches reporting_standard.md §1 (10 sections, in order).
[ ] Every required figure present, or "N/A — reason" stated.
[ ] Every prose number traceable to a CSV.
[ ] Gross + net side by side in headline tables and on every figure where applicable.
[ ] Verdict ordered by importance, not by recency of discovery.
[ ] All [TODO]s are missing data/compute, not missing prose.
[ ] Five-category exit_reason vocabulary used; no novel strings.
[ ] MLflow attachment status stated.
```
